# AEB 算法快速验证方案（不跑 CARLA）

> 面向 AEB 算法设计者的方案：在不运行 CARLA 仿真的前提下，快速验证规则式 AEB 算法的可行性与性能。
> 行业依据：SIL（软件在环）验证与 HIL（硬件在环）实测平均偏差仅 1.7m（MDPI 2022），SIL 阶段足够支撑算法初版的迭代验证。

---

## 一、算法接口定义

### 输入（8 个）

| # | 输入 | 含义 |
|:-:|:---|:---|
| 1 | 疲劳等级 | DMS 端输出，L0~L3（正常→重度疲劳） |
| 2 | 自身车速 | 本车当前速度 |
| 3 | 障碍物速度 | 目标障碍物速度 |
| 4 | 障碍物加速度 | 目标障碍物加速度（可预测其运动趋势） |
| 5 | 自身前进方向 | 本车航向角 |
| 6 | 障碍物前进方向 | 障碍物航向角 |
| 7 | 相对距离 | 两车距离 |
| 8 | 驾驶员控制意图与算法反应的一致性 | 驾驶员操作与算法判断是否一致 |

### 输出（3 个）

| # | 输出 | 含义 |
|:-:|:---|:---|
| 1 | 制动等级 | 分级制动（如无制动/预警/L1~L3） |
| 2 | 控制权重 | 系统接管程度（0~1，越大接管越多） |
| 3 | 制动加速度 | 具体制动命令（m/s²） |

---

## 二、从接口读出的算法特征（决定了验证方案怎么选）

| 特征 | 依据 | 对验证的影响 |
|:---|:---|:---|
| **人机共驾 / 仲裁型** | 输入 8（意图一致性）+ 输出 2（控制权重） | 不是"遇障就刹"的纯 AEB，而是根据驾驶员状态决定接管程度的算法 → 必须设计专门的"驾驶员意图场景" |
| **疲劳调制** | 输入 1（疲劳等级） | 触发阈值、制动强度应按疲劳等级变化 → 需验证调制曲线（L0 应退化为基础行为，L3 应提前介入） |
| **支持非共线场景** | 输入 5、6（双方向角） | ⚠️ **1D 纵向仿真不够用**，方向角必须有意义的输入 → 需要 2D 仿真 |
| **预测型** | 输入 4（障碍物加速度） | 能处理时变目标（减速/加速/起步）→ 场景库要覆盖加速度变化 |
| **三级输出** | 制动等级 + 加速度 + 权重 | 状态机转移、数值命令、仲裁权重三类都要验证 |

## 三、候选方案对比

| 方案 | 能验证什么 | 盲区 / 成本 |
|:---|:---|:---|
| **① 纯函数单元测试** | TTC 计算、状态转移、仲裁分支、边界值、权重合法性 | 验证不了闭环结果（到底刹不刹得住）；成本极低 |
| **② 1D 纵向闭环仿真** | 纵向场景（CCR 系列）碰撞避免、疲劳调制、加速度维度 | ❌ 方向角输入被冻结为常量 → 等于这个输入白设计了 |
| **③ 2D 运动学闭环仿真**（推荐） | ②的全部 + 交叉/斜向场景、方向角参与评估、时变目标 | 自写 ~200 行，成本仍很低 |
| **④ CSV 轨迹回放** | 任意轨迹（含转向、变速）离线回放、CI 自动回归 | 需先有轨迹数据（可由 ③ 导出） |
| **⑤ HighwayEnv** | 标准 2D 多车环境（Gym） | 对规则式算法收益不大，不如自写 2D 可控 |

**结论：方向角输入的存在，把"② 1D"升级为"③ 2D"**——状态从一维 `(v, d)` 换成二维 `(x, y, heading, v)`，实现成本增加不多，但方向角、交叉场景全部变得可验证。

## 四、推荐方案：三明治组合（① + ③ + ④）

```
┌─ Layer 1  单元测试（白盒，半天）───────────────────────┐
│  TTC / 状态机 / 仲裁分支 / 边界值 / 疲劳调制表单调性      │
│  权重范围合法性（0~1，危险时单调递增）                    │
├─ Layer 2  2D 运动学闭环仿真（核心，2~3 天）───────────────┤
│  场景库：Euro NCAP 纵向 + 交叉/斜向 + 疲劳调制 + 意图场景 │
│  车辆执行模型：制动延迟 / 最大减速度 / jerk               │
│  驾驶员模拟器：踏板信号 + 意图标志（无操作/正确制动/误踩） │
│  指标：Euro NCAP 颜色网格 + 权重曲线 + 触发 TTC + 舒适性  │
├─ Layer 3  CSV 轨迹回放（收尾，半天）─────────────────────┤
│  场景导出 CSV（含方向角/疲劳等级/意图列）                 │
│  复杂轨迹手工造（转向接近、鬼探头、变速）                 │
│  CI 自动回归：每次改算法全量重跑                         │
└──────────────────────────────────────────────────────────┘
```

三层职责分工：
- **① 抓逻辑 bug**：算法内部正确性
- **③ 抓行为 bug**：闭环下刹不刹得住、什么时候刹、权重怎么变
- **④ 抓回归**：可复现、可追溯、团队协作不互相踩

## 五、场景库设计（按算法输入定制）

### 场景族 1：Euro NCAP 纵向（基础制动对照基线）

| 场景 | 定义 | 网格 |
|:---|:---|:---|
| CCRs 前车静止 | 自车撞静止车辆 | 10~50 km/h × 5km/h 步进 |
| CCRm 前车匀速 | 前车恒定速度 | 30~80 km/h × 5km/h 步进 |
| CCRb 前车制动 | 双方 50km/h，前车 -2/-6 m/s² | 12m / 40m 车距 |

方向角 = 0，冻结此维度作基线。

### 场景族 2：方向角场景（解锁 2D 输入）

| 场景 | 设置 | 验证点 |
|:---|:---|:---|
| 交叉穿越 | 自车直行，障碍物 90° 横穿 | 方向角是否参与危险度评估 |
| 斜向接近 | 45° 斜插 | 权重是否随夹角变化 |
| 同向变道 | 障碍物斜切入本车道 | 时变方向角跟踪 |

### 场景族 3：疲劳调制（对接 DMS 端）

**同一场景 × 4 个疲劳等级（L0~L3）**，检查：
- [ ] 触发 TTC 是否随疲劳等级提前（L3 应比 L0 更早介入）
- [ ] 制动权重是否随疲劳等级抬高
- [ ] L0 时是否退化为普通 AEB 行为（不误触发）

### 场景族 4：驾驶员意图仲裁（算法核心价值）

| 驾驶员行为 | 期望的算法反应 |
|:---|:---|
| 无操作（疲劳/分心） | 权重 → 1.0，系统全权接管 |
| 正确制动（看到危险） | 权重 → 0，让位给驾驶员 |
| 错误加速（误踩油门） | 压制油门，权重保持高位 |
| 半踩刹车（犹豫） | 权重取中间值，分级介入 |

### 场景族 5：时变目标

- 障碍物先匀速后急刹（CCRb 强化版）
- 障碍物先静止后起步（"鬼探头"变体）
- 障碍物加速度抖动（测抗抖/滤波）

## 六、评测指标与验收标准

### Euro NCAP 颜色网格（现成的评分体系）

| 颜色 | 撞击速度 Vimpact | 评分 |
|:---|:---|:---:|
| 🟢 绿 | 0 ~ 5 km/h（完全避免/几乎避免） | 1.0 |
| 🟡 黄 | 5 ~ 15 km/h | 0.75 |
| 🟠 橙 | 15 ~ 30 km/h | 0.5 |
| 🟤 棕 | 30 ~ 40 km/h | 0.25 |
| 🔴 红 | ≥ 40 km/h（几乎未减速） | 0 |

### 汇总指标

- 碰撞避免率（绿色占比）
- 平均速度降低量（Euro NCAP：减速 ≥20 km/h 得 0.25 分）
- 制动介入时 TTC（越早越安全，但不能早到误触发）
- 最大减速度 / jerk（舒适性，>8 m/s² 判不适）
- 权重曲线的单调性与调制正确性

### 可抄的验收标准（来自开源 AEB 项目，Euro NCAP CCR 场景）

| 场景 | 条件 | 验收标准 |
|:---|:---|:---|
| CCRs | 自车 40 km/h，前车静止 | 完全停止 或 剩余速度 <5 km/h |
| CCRm | 自车 50 km/h，前车 20 km/h | 避免碰撞 或 撞击速度降低 ≥20 km/h |
| CCRb | 双方 50 km/h，前车 -2 m/s² | 避免碰撞 或 撞击速度 <15 km/h |

## 七、落地步骤（5 天）

| 天 | 内容 | 产出 |
|:-:|:---|:---|
| 1 | 算法抽成纯函数（8 输入 → 3 输出），pytest 单元测试 | 单元测试集 |
| 2 | 2D 运动学引擎（~200 行）+ 车辆执行模型 + 驾驶员模拟器 | 仿真引擎 |
| 3 | 实现 5 族场景库（参数化网格） | 场景库 |
| 4 | 跑全场景 → 颜色网格 + 权重曲线 + 误触发测试 | 第一版验证报告 |
| 5 | 场景导出 CSV，接 CI 回归 | 自动化回归流水线 |

**工程化要点**：场景定义、车辆模型参数、AEB 决策函数三件事完全解耦（独立文件），谁改都不影响别人。

---

## 八、与 DMS 端的联动（后期集成点）

- 疲劳调制场景需要**真实的疲劳等级分布** → DMS 端队友完成数据采集、评分器阈值调优后，可将"真实疲劳特征序列"作为 CSV 场景的一列喂给 AEB 验证
- 打通后：`真实疲劳序列 → AEB 决策 → 制动行为` 全链路可验证，是项目整体验收的核心证据链
