## 经验结论

疲劳检测领域的核心瓶颈不是模型架构不够好，而是**评估体系不可比**——不同论文用不同验证协议、数据集和指标声称自己最好，但这些数字之间无法互相比较。对本科 SRTP 项目而言，只要在实验设计上采纳标准化评估框架，就能在方法论层面超越大多数同类工作。

## 技术细节

### 一、可直接用于项目的方法

#### 1. 三层验证协议（替代简单的随机划分）

实验室常用但不可靠的做法：

```
所有帧 → 随机打乱 → 80/20 划分 → 训练/测试
问题：同一人的相邻帧同时出现在训练集和测试集，准确率虚高
```

应采用的三种协议：

| 协议 | 方法 | 难度 | 在我们的项目中 |
|------|------|:--:|------|
| **within-subject** | 自己的数据训练+测试自己 | 低 | 当前 CalibTool 已做 |
| **leave-one-subject-out** | 标定 N 人 → 轮换留一人做测试 | 中 | 标定 3-5 人后即可做 |
| **cross-condition** | 晴天标定 → 雨天/夜间/逆光测试 | 中 | CARLA 多场景已支持 |

**论文写法**：

> "我们在三个层次的验证协议下评估系统：within-subject（单人）、leave-one-subject-out（跨被试）、cross-condition（跨场景）。三种协议下的性能差异揭示了评估协议选择对结论的决定性影响——这正是 Hassan et al. (2026) 在其 DMS 综述中强调的关键方法论问题。"

#### 2. 七指标评估矩阵（替代单独报 accuracy）

| 指标 | 含义 | 为什么重要 | 怎么算 |
|------|------|------|------|
| **Accuracy** | 整体正确率 | 传统指标，报一下但不做主要结论 | 正确帧/总帧 |
| **Precision** | 报警 N 次，几次真疲劳 | 衡量「扰民程度」 | TP/(TP+FP) |
| **Recall** | 真疲劳 100 次，抓了几次 | 衡量「安全性」 | TP/(TP+FN) |
| **F1-score** | P 和 R 的调和平均 | 平衡指标 | 2PR/(P+R) |
| **PR-AUC** | Precision-Recall 曲线下面积 | 不被类别不平衡欺骗（综述核心推荐） | sklearn.metrics.auc |
| **FAR** | 每小时误报次数 | 实用指标：误报太多驾驶员关系统 | FP/总时长(h) |
| **Recall@FAR** | 误报控制在 1 次/h 时的召回率 | 安全-扰民 trade-off 的操作点 | 遍历阈值找对应点 |

**在 CARLA 中计算示例**：

```python
# 60 分钟测试，30 FPS
total_frames = 60 * 60 * 30  # = 108,000
fatigue_gt = ground_truth_labels   # 你的疲劳真值标注
fatigue_pred = model_predictions   # 系统输出

from sklearn.metrics import precision_recall_curve, auc, confusion_matrix

precision, recall, _ = precision_recall_curve(fatigue_gt, fatigue_pred)
pr_auc = auc(recall, precision)

tn, fp, fn, tp = confusion_matrix(fatigue_gt, fatigue_pred).ravel()
far_per_hour = fp / (total_frames / 30 / 3600)  # 折算到每小时
```

#### 3. 疲劳分数的操作化定义

不要写「大概疲劳了就报警」，而是给出基于特征的精确计算公式。这是你当前方案的核心——**多特征线性加权 fatigue_score**，已在 [[AEB决策层学习化升级方案]] 中记录：

```python
# 每个特征归一化到 [0,1] 后加权求和
fatigue_score = (
    0.30 * normalize_eye_closed(ear_duration) +  # 连续闭眼时长
    0.25 * perclos +                               # PERCLOS 已是 [0,1]
    0.15 * normalize_yawn(yawn_per_min) +         # 哈欠频率
    0.15 * normalize_pitch(pitch_deg) +            # 低头角度
    0.10 * normalize_yaw(yaw_deg)                  # 偏头角度
)
# 各归一化函数定义见 AEB 升级方案 §1.5.2
```

**为什么重要**：Hassan et al. 指出大多数研究的 ground truth 定义不清晰——有的是 KSS≥7 算疲劳，有的是 KSS≥8，互相无法比较。你的 fatigue_score 是**纯粹基于可测量物理特征的计算公式**，不依赖主观量表，因此具有天然的跨研究可复现性。在论文中把这个公式写出来本身就是贡献点。

### 二、可写入文献综述的部分

#### 写法1：领域现状总结

> "驾驶员疲劳检测技术经历了从单模态规则（PERCLOS 阈值）到深度学习（CNN、LSTM）再到 Transformer 架构的演进。在受控条件下，单模态方法准确率达 80-90%，多模态融合可达 93% 以上。然而，Hassan et al. (2026) 在其对 70 篇论文的系统综述中指出，这些数字高度依赖验证协议——跨被试或跨数据集评估时，准确率通常下降 10-20%。这一发现表明，该领域的核心挑战已从模型设计转向评估方法论和泛化能力。"

#### 写法2：指出现有研究的方法论缺陷

> "现有疲劳检测研究存在显著的方法论缺陷。Hassan et al. (2026) 识别出三个关键差距：(1) 大多数研究采用 subject-dependent 验证协议，将同一驾驶员的数据既用于训练又用于测试，导致性能被高估；(2) 评价指标以 accuracy 为主，忽视了疲劳作为低发生率事件的类别不平衡问题——一个永远输出'清醒'的分类器可达 95% accuracy 但毫无实用价值；(3) 仅 19.2% 的研究讨论了模型可解释性，12.8% 涉及个性化，而这两者恰恰是真实部署中用户信任和法规合规的前提。本研究在实验设计中针对性地回应了这些问题。"

#### 写法3：论证你们的方法选择

> "我们选择 MediaPipe 关键点 + 几何特征 + 阈值规则的技术路线，而非直接采用端到端深度学习模型，主要基于以下考虑。首先，Hassan et al. (2026) 的综述表明，尽管深度学习模型在 within-dataset 评估中准确率可达 99% 以上，但其跨域泛化能力尚未得到充分验证，且可解释性严重不足。其次，我们的方法中 EAR/MAR/HeadPose 每个特征都有明确的生理学和几何学含义，每级疲劳判定都有可追溯的规则链——这种可解释性在仅 19.2% 的疲劳检测研究中被讨论，是一个被严重低估的优势。"

#### 写法4：论证你们的多特征融合方法

> "单一疲劳特征已被证明不可靠——眼部特征受光照和眼镜影响，嘴部特征易被说话和微笑干扰，头部姿态需区分疲劳低头和正常看仪表盘。因此，我们采用眼-嘴-头多特征融合方案，这与 Hassan et al. (2026) 综述中推荐的'多模态混合架构'方向一致。不同的是，我们采用线性加权而非黑箱融合，以保持每个特征的独立可解释性。"

#### 写法5：论文的创新点表达

可以把综述中的行业痛点直接转化为你的创新点：

| 综述说「大家都没做」 | 你可以说「我们做了」 |
|------|------|
| 不区分验证协议 | "我们在三层次验证协议下评估" |
| 只报 accuracy | "报告七项指标：Accuracy、Precision、Recall、F1、PR-AUC、FAR、Recall@FAR=1/h" |
| 阈值拍脑袋 | "通过 CalibTool 对每位被试进行个性化标定，阈值有数据支撑" |
| 不讨论可解释性 | "每个特征有明确物理含义，每级判定可追溯规则链" |
| ground truth 模糊 | "fatigue_score 通过多特征线性加权公式精确定义，每个特征的归一化函数和权重均有明确物理依据" |

## 项目采用建议

### 建议采用

- [x] 三层验证协议（within-subject / leave-one-subject-out / cross-condition）
- [x] 七指标评估矩阵（Accuracy + P + R + F1 + PR-AUC + FAR + Recall@FAR）
- [x] fatigue_score 多特征线性加权公式写入论文
- [x] CalibTool 标定多人数据（≥3 人）
- [x] 在论文中主动论述可解释性作为方法优势
- [x] 在 limitation 中坦诚写：仅仿真验证、离线标定的漂移问题、光照鲁棒性待优化

### 暂不采用

- 多模态生理信号融合（EEG/ECG）——需要额外硬件，超出本科 SRTP 范围
- 端到端深度学习方案——与当前「规则优先、可解释优先」的定位不符
- 在线自适应阈值——超出当前版本范围，可作为「未来工作」在论文中提一句

### 需要实验验证

- leave-one-subject-out 验证下 PR-AUC 的实际降幅（预计 10-20%，需要实测数据支撑）
- 不同 CARLA 天气条件下阈值稳定性的定量分析

## 可写入综述的表达

> "Hassan et al. (2026) 在其系统综述中指出，疲劳检测领域存在三个关键瓶颈：端到端延迟（嵌入式平台约 100-300ms）、跨域泛化（跨被试/跨数据集准确率下降 10-20%）、以及隐私与可接受性。此外，仅 19.2% 的研究讨论了模型可解释性，12.8% 涉及个性化。本研究在实验设计中回应了这些方法论关切：采用三层次验证协议评估泛化能力，报告包括 PR-AUC 在内的七项指标以克服类别不平衡问题，并通过特征级可解释的规则链设计保证了判定过程的透明度。"

> "从技术演进角度看，疲劳检测经历了 PERCLOS 规则阈值 → CNN → CNN+LSTM → Transformer/ViT 的发展路径。然而，Hassan et al. (2026) 对 70 项研究的系统分析表明，模型复杂度的提升并未带来相应比例的泛化能力提升——Vision Transformer 在 within-dataset 评估中可达 99% 以上准确率，但跨数据集优势不明显。这一发现支持我们在本科 SRTP 阶段采用'几何特征 + 多特征融合规则'而非直接追逐最深模型的策略。"
