# Sensors 2024, 24(19):6261 文献综述素材

## 1. 文献信息

**题名**：A Real-Time Embedded System for Driver Drowsiness Detection Based on Visual Analysis of the Eyes and Mouth Using Convolutional Neural Network and Mouth Aspect Ratio

**作者**：Ruben Florez, Facundo Palomino-Quispe, Ana Beatriz Alvarez, Roger Jesus Coaquira-Castillo, Julio Cesar Herrera-Levano

**出处**：Sensors, 2024, 24(19): 6261

**DOI**：10.3390/s24196261

**建议归类**：基于视觉特征的驾驶员疲劳检测；眼部状态识别；打哈欠检测；嵌入式实时疲劳预警系统。

## 2. 给综述同学的一句话摘要

Florez 等人提出了一种面向车载实时应用的混合式驾驶员疲劳检测系统：用 CNN 判断眼部区域是否处于疲劳状态，用嘴部纵横比 MAR 判断打哈欠，并将系统部署在 NVIDIA Jetson Nano 与近红外摄像头上。该工作适合作为“视觉特征 + 轻量化嵌入式部署”的代表性文献。

## 3. 这篇论文适合放在综述的哪个位置

这篇论文不适合只作为“背景介绍”引用，而更适合放在以下小节中：

1. **基于视觉特征的疲劳检测方法**：论文同时使用眼部和嘴部信息，体现了从单一眼部特征向多区域视觉特征融合的思路。
2. **基于深度学习的眼部状态识别**：论文比较了 InceptionV3、VGG16、ResNet50V2 和自建 DD-AI 网络。
3. **嵌入式实时疲劳检测系统**：论文不仅做离线分类，还在 Jetson Nano 上进行车载实测，给出了准确率和帧率。
4. **基于 MAR 的打哈欠检测**：论文将 MAR 作为嘴部疲劳特征，用阈值判断打哈欠。

## 4. 方法核心

该系统采用混合式判定逻辑：眼部疲劳由 CNN 判断，嘴部打哈欠由 MAR 阈值判断。

### 4.1 输入与硬件

- 传感器：近红外 NIR 摄像头。
- 处理平台：NVIDIA Jetson Nano。
- 显示与报警：7 英寸触摸屏和扬声器。
- 目标场景：车内实时监测，尤其考虑夜间或光照变化条件。

### 4.2 视觉处理流程

1. 摄像头采集驾驶员面部图像。
2. 使用 MediaPipe Face Mesh 提取 468 个面部关键点。
3. 选取眼部 ROI 和嘴部 ROI。
4. 对眼部 ROI 进行区域修正，减少头部转动或倾斜造成的信息丢失。
5. 用 CNN 对眼部状态进行二分类：drowsy / not drowsy。
6. 用 MAR 计算嘴部张开程度，判断是否打哈欠。
7. 若检测到闭眼疲劳或打哈欠，触发声音报警。

### 4.3 眼部 CNN

论文比较了四种 CNN：

| 模型 | 类型 | 用途 |
| --- | --- | --- |
| InceptionV3 | 迁移学习 | 眼部状态二分类 |
| VGG16 | 迁移学习 | 眼部状态二分类 |
| ResNet50V2 | 迁移学习 | 眼部状态二分类 |
| DD-AI | 作者自建网络 | 眼部状态二分类 |

DD-AI 的特点是结构相对轻量，包含三个卷积层、最大池化、dropout、全连接层和 softmax 输出。论文使用 Grad-CAM 对模型关注区域进行解释，认为 DD-AI 更集中关注眼部区域。

### 4.4 嘴部 MAR

论文使用 8 个嘴部关键点计算 Mouth Aspect Ratio。其逻辑是：嘴部纵向距离越大、横向距离相对越小，MAR 值越高，越可能处于打哈欠状态。

论文设置的打哈欠触发规则为：

- MAR 指数大于 55；
- 且持续超过 5 秒；
- 满足条件后触发报警。

眼部疲劳触发规则为：

- CNN 判断眼部 ROI 属于疲劳状态的概率高于 95%；
- 且闭眼时间超过 300 ms；
- 满足条件后触发报警。

## 5. 数据集与实验设计

论文使用 NITYMED 数据集。该数据集包含夜间打哈欠、微睡眠、眨眼和驾驶员分心等场景，具有驾驶场景真实性。

论文从 NITYMED 的 1080p 视频中选取 6 个视频，提取眼部 ROI 后构建二分类数据集：

| 数据集 | Drowsy | Not Drowsy | 总量 |
| --- | ---: | ---: | ---: |
| 训练集 | 2380 | 2380 | 4760 |
| 验证集 | 510 | 510 | 1020 |
| 测试集 | 510 | 510 | 1020 |
| 总计 | 3400 | 3400 | 6800 |

训练设置包括：

- 每种 CNN 进行 10 次训练实验；
- epoch 为 30；
- batch size 为 32；
- 使用 ADAM 优化器；
- 对训练图像进行数据增强；
- VGG16、ResNet50V2、DD-AI 输入尺寸为 64×64，InceptionV3 输入尺寸为 75×75。

## 6. 关键结果

### 6.1 离线测试结果

在测试集上，DD-AI 的平均准确率最高：

| 模型 | 测试集平均准确率 |
| --- | ---: |
| InceptionV3 | 98.95% |
| VGG16 | 98.33% |
| ResNet50V2 | 99.49% |
| DD-AI | 99.88% |

论文还强调，对于疲劳检测任务，drowsy 类别的召回率很重要，因为漏检疲劳状态比误报更危险。DD-AI 在 drowsy 类别召回率上也表现最好。

### 6.2 模型规模与响应时间

| 模型 | 参数量 | 文件大小 | 响应时间 |
| --- | ---: | ---: | ---: |
| InceptionV3 | 22,828,286 | 98,055 KB | 51.01 ms |
| VGG16 | 15,740,190 | 69,586 KB | 39.00 ms |
| ResNet50V2 | 27,662,302 | 140,594 KB | 60.02 ms |
| DD-AI | 6,448,002 | 75,618 KB | 33.00 ms |

这说明 DD-AI 不仅准确率高，而且推理响应时间较短，较适合嵌入式部署。

### 6.3 Jetson Nano 车载实测结果

论文将系统安装在车内进行测试。硬件实测中，DD-AI 仍然表现最好：

| 模型 | 车载实测准确率 | FPS |
| --- | ---: | ---: |
| InceptionV3 | 92.45% | 9-14 |
| VGG16 | 90.27% | 9-14 |
| ResNet50V2 | 95.86% | 9-14 |
| DD-AI | 96.55% | 9-14 |

论文认为 10 fps 左右可以满足眨眼检测的最低需求，因此 9-14 fps 对实时疲劳预警具有一定可用性。

## 7. 论文贡献

1. 提出眼部 CNN 与嘴部 MAR 相结合的混合式疲劳检测方案。
2. 对眼部 ROI 提取进行了修正，使其更适应头部转动和倾斜。
3. 比较了三种迁移学习 CNN 与自建 DD-AI 网络。
4. 使用 Grad-CAM 分析模型关注区域，增强了模型解释性。
5. 在 Jetson Nano 上进行车载环境测试，给出真实部署条件下的准确率与帧率。
6. 引入 NIR 摄像头，增强夜间与弱光条件下的可用性。

## 8. 局限与注意点

这篇论文的结果有参考价值，但不能直接照搬为项目最终结论，需要注意以下问题：

1. **数据规模有限**：眼部分类数据集来自 NITYMED 中选取的 6 个视频，虽然构造了 6800 张图像，但主体和场景仍有限。
2. **MAR 阈值依赖经验**：打哈欠阈值 55 是通过试错得到的，换摄像头、距离、脸型或关键点算法后可能需要重新标定。
3. **硬件结果低于离线结果**：DD-AI 离线测试准确率为 99.88%，但车载实测为 96.55%，说明真实部署会带来性能下降。
4. **MediaPipe 带来帧率损失**：论文指出 MediaPipe 会降低系统帧率，这是实时系统设计中的关键瓶颈。
5. **遮挡和个体差异仍是问题**：口罩、眼镜、脸部未完全可见等情况可能影响泛化能力。
6. **疲劳定义偏视觉状态**：论文主要使用闭眼和打哈欠作为疲劳表现，未结合方向盘、车道、心率、EEG 等信息。

## 9. 对我们 SRTP 项目的启发

### 9.1 可借鉴点

- 可以采用“眼部状态 + 嘴部状态”的双线索判定，而不是只依赖单一特征。
- 对本科项目而言，MAR/EAR/PERCLOS 等几何特征可解释性强，适合作为初版判定逻辑。
- 如果使用 CNN，应该优先考虑轻量模型，而不是直接堆大模型。
- 需要把离线准确率和实时运行帧率同时作为评价指标。
- 如果项目场景涉及夜间或弱光，应考虑红外摄像头或补光方案。

### 9.2 不宜直接照搬的地方

- 不建议直接使用论文中的 MAR=55 作为固定阈值，需要根据摄像头距离、关键点输出和本组数据重新标定。
- 不建议只报告模型准确率，还要报告召回率，尤其是疲劳类召回率。
- 不建议只在公开数据集上验证，至少要做一组本项目采集环境下的测试。

### 9.3 可以形成的项目技术路线

对于本科 SRTP，建议采用逐步递进路线：

1. 第一阶段：MediaPipe 提取眼部和嘴部关键点。
2. 第二阶段：用 EAR、MAR、闭眼时长、打哈欠持续时间构建规则判定。
3. 第三阶段：采集本组数据，验证阈值稳定性。
4. 第四阶段：如规则法不稳定，再引入轻量 CNN 或分类器判断眼部状态。
5. 第五阶段：在真实运行环境下测试 FPS、误报率和漏报率。

## 10. 可直接用于文献综述的中文段落

### 10.1 基于视觉特征的疲劳检测

在基于视觉特征的驾驶员疲劳检测研究中，眼部状态和嘴部状态是常用的行为线索。Florez 等人提出了一种结合眼部 CNN 分类与嘴部 MAR 特征的混合式疲劳检测方法，通过 MediaPipe 提取面部关键点，并分别构建眼部 ROI 和嘴部 ROI。其中，眼部区域用于 CNN 二分类，嘴部区域通过 MAR 判断打哈欠状态。该方法体现了视觉疲劳检测从单一眼部特征向多区域特征融合发展的趋势。

### 10.2 深度学习与传统几何特征结合

该研究并未完全依赖深度学习模型，而是将 CNN 用于眼部疲劳状态识别，同时使用可解释性较强的 MAR 几何特征进行打哈欠检测。这种混合策略兼顾了深度学习在视觉分类中的表达能力和传统几何特征在规则判定中的可解释性，对资源受限的实时疲劳检测系统具有参考价值。

### 10.3 嵌入式实时部署

与仅在离线数据集上验证模型的研究不同，Florez 等人将疲劳检测系统部署在 NVIDIA Jetson Nano 上，并在车载环境中进行了测试。实验结果显示，自建 DD-AI 网络在测试集上达到 99.88% 的平均准确率，在车载实测中达到 96.55% 的准确率，运行帧率为 9-14 fps。该结果表明，轻量化 CNN 与视觉几何特征结合后具有一定的嵌入式实时应用潜力。

### 10.4 研究局限

尽管该系统在 Jetson Nano 平台上取得了较好的准确率和实时性，但其性能仍受摄像头视角、面部遮挡、个体差异以及 MediaPipe 关键点检测速度影响。此外，论文中的 MAR 阈值通过经验试验得到，迁移到其他设备或数据采集环境时仍需重新标定。因此，在实际项目中应同时关注模型准确率、疲劳类召回率、帧率以及真实场景下的鲁棒性。
