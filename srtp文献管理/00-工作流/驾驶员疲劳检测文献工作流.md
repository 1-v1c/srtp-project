# 驾驶员疲劳检测文献工作流

## 你的任务定位

你负责的是 SRTP 项目中的“驾驶员疲劳检测判定部分”。读文献时不要把目标设成“看懂整篇论文”，而要把每篇论文转化为三类成果：

1. 项目能借鉴的技术经验
2. 疲劳判定模块的设计依据
3. 能交给综述同学直接使用的文献综述素材

每篇论文至少产出一张“论文阅读卡”。如果论文质量较高，再继续拆成“方法经验卡”和“综述素材卡”。

## 文件夹分工

- `01-论文PDF/`：保存论文 PDF 原文。
- `02-论文阅读卡/`：每篇论文一张阅读卡，记录“这篇论文到底做了什么”。
- `03-方法与经验卡/`：从论文中抽取可复用经验，如疲劳特征、判定规则、模型结构、实时部署方案。
- `04-综述素材/`：写给负责综述的同学，强调研究脉络、代表方法、优缺点和可引用观点。
- `05-项目决策记录/`：沉淀你们项目自己的选择，例如为什么用眼部特征、为什么不用 EEG、阈值怎么定。
- `99-模板/`：Obsidian 模板，之后复制使用。

## 单篇论文处理流程

### 1. 录入论文

文件命名建议：

```text
期刊-年份-卷期-文章号-短标题.pdf
```

例如：

```text
Sensors-2024-24-6261-driver-drowsiness-cnn-mar.pdf
```

对应阅读卡命名：

```text
论文卡-Sensors-2024-6261-driver-drowsiness-cnn-mar.md
```

### 2. 快速筛选

先判断这篇论文值不值得深读：

- 是否和“驾驶员疲劳检测/判定”直接相关？
- 是否涉及眼部、嘴部、头部姿态、行为特征或多模态疲劳判断？
- 是否有实验指标、数据集、模型结构、实时性说明？
- 是否能给你们项目提供可执行经验？

如果只能提供背景介绍，可以只做综述素材；如果有算法、指标、实验过程，就做完整阅读卡。

### 3. 深读结构

按这个顺序读，不要从头到尾硬啃：

1. Abstract：弄清楚研究目标、方法、结果。
2. Introduction：找研究动机和已有方法不足。
3. Method：重点读特征、模型、疲劳判定逻辑。
4. Experiments：记录数据集、评价指标、对比方法。
5. Results：抓有效结论，不要抄表格。
6. Discussion/Conclusion：找作者承认的限制和未来工作。

### 4. 抽取项目经验

对驾驶员疲劳判定模块，重点抽这些内容：

- 疲劳信号来源：眼睛、嘴巴、头部姿态、车道偏移、方向盘、EEG 等。
- 判定特征：EAR、MAR、PERCLOS、眨眼频率、打哈欠、闭眼时长、头部点头。
- 判定方式：阈值规则、传统机器学习、CNN/RNN/Transformer、多模态融合。
- 实时性：FPS、延迟、硬件平台、嵌入式部署难点。
- 数据集：采集人数、场景、标注方式、是否真实驾驶。
- 评价指标：Accuracy、Precision、Recall、F1、AUC、误报率、漏报率。
- 失败场景：眼镜、光照、遮挡、摄像头角度、个体差异、夜间驾驶。

### 5. 交付综述素材

给综述同学的内容不要是“论文摘要合集”，而要是可组合的综述段落材料：

- 这篇论文属于哪类方法？
- 它解决了什么问题？
- 它相比前人改进在哪里？
- 它的结果说明了什么？
- 它的局限是什么？
- 它能支持综述中的哪一个观点？

## Codex 协作方式

你可以把任务分给 Codex，但每次要让它输出结构化结果，而不是“总结一下论文”。

### 快速理解论文

```text
请基于这篇 PDF，按“研究问题-方法-实验-结果-局限-对我们项目的启发”总结，不要泛泛复述摘要。
```

### 抽取疲劳判定经验

```text
请只关注驾驶员疲劳检测的判定部分，提取论文中的输入特征、疲劳标签、判定规则/模型、评价指标、实时部署条件，以及对我们本科 SRTP 项目的可借鉴点。
```

### 生成综述素材

```text
请把这篇论文转化为文献综述素材，按“研究类别、代表性工作、主要贡献、优点、局限、可用于综述的句子”输出。
```

### 对比多篇论文

```text
请比较这些论文在疲劳判定特征、模型方法、数据集、实时性、优缺点方面的差异，并给出适合我们项目采用的路线建议。
```

## 每周整理节奏

建议一周一个小循环：

1. 收集 3-5 篇候选论文。
2. 快速筛掉弱相关论文。
3. 精读 1-2 篇高相关论文。
4. 每篇形成阅读卡。
5. 把可复用内容拆成方法经验卡。
6. 给综述同学输出一份周同步材料。

## 最终沉淀目标

经过几周后，你应该拥有：

- 一批结构一致的论文阅读卡
- 一个疲劳判定方法对比表
- 若干可直接放入综述的主题段落
- 一份项目技术路线依据
- 一份你们项目不采用某些方法的理由

这套东西比单纯“读过多少篇论文”更重要。
