# SRTP 代码优化记录

每批代码修改新增一份 Markdown 记录，适用于仓库所有模块。文件统一存放在 `docs/code-optimization/`，命名为 `YYYY-MM-DD-模块-改动摘要.md`。文件名中的模块和改动摘要使用小写英文短词，用连字符连接。日期使用北京时间。同一批改动覆盖多个模块时，在记录中逐项写明。

发布记录时链接到对应提交，并注明代码所在分支及合入状态。验证一节写实际运行的测试、结果和验证范围。

## 固定格式

```markdown
# <模块> <改动标题>

## 基本信息

- **修改日期** YYYY-MM-DD（北京时间）
- **模块** <模块或子系统>
- **涉及文件** <文件或目录>

## 改动与改善

- <原问题、具体改动、实现的功能或改善>

## 验证结果

- <用例、运行方式和可量化的结果>
- **验证范围** <已验证范围与待验证项>

## 代码与交付状态

- **代码** <分支、提交链接和合入状态>
```
