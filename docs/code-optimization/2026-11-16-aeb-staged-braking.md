# AEB 分阶段制动与释放滞回

## 基本信息

- **修改日期** 2026-11-16（北京时间）
- **模块** AEB 纵向制动决策、指令整形和仿真验证
- **涉及文件** `brake_algorithm.py`、`longitudinal_brake.py`、`data_box.py`、`tests/test_brake_algorithm.py`、`scripts/simulate_staged_brake.py`

## 改动与改善

- 经上游确认并符合纵向几何约束的前方目标，按保险杠净距、目标当前减速度、执行延迟及减速度建立速度预测未来最小车距。在轻制动余量不足时直接升到更强制动。非纵向目标沿用既有决策。
- `DataBox` 按目标保存制动状态。退出检查先预测减小制动力所需的净距，确认释放/降级条件连续维持 0.30 s 后才切换。经上游确认的目标失效或目标 ID 变化会清除旧状态。
- 轻制动目标为 3.0 m/s²，低接近速度时为 1.5 m/s²。中等目标为 5.5 m/s²。发出的轻制动、中等制动和释放指令分别采用 6、15、5 m/s³ 的速率上限，并受执行器上限限制。紧急阶段用执行器允许的较快建立速率。所有参数为软件在环候选。
- 有效疲劳等级增加早期介入的净距余量。疲劳无效时按 L0，紧急升级依据预测净距。记录原始减速度目标 `brake_reference`、整形后的 `aeb_decel`、实际仲裁命令 `a_final` 和制动阶段。常规入口为 `update_brake_result(box, dt_sec=...)`，默认周期 20 ms。中心距供旧 TTC 使用，新策略使用同步提供的 `bumper_gap_m`。

## 验证结果

- `python -m unittest discover -s tests -v` 通过 19 项，覆盖低速净距、限速爬升、释放确认、紧急升级、人工制动、疲劳过期和目标切换。
- `python scripts/simulate_staged_brake.py --output-dir artifacts --plot` 重放对照，输出 PNG 和两份 CSV。绘图依赖 Matplotlib。两版使用同一输入、执行器和驾驶员无操作设定。控制 50 Hz，车辆积分 200 Hz，最长 30 s。基线取 `3306de0` 的净距制动策略。常规执行器用 0.15 s 延迟和 30 m/s³ 的建立/释放上限，低速和压力工况用 0.30 s 和 15 m/s³。
- 切换数统计 0.1 m/s² 附近的制动开关，计入初始已激活。实际 jerk 由 5 ms 的相邻实际加速度计算，忽略低于或等于 0.05 m/s 的钳零邻域及接触边沿。报告的实际 jerk 与 50 Hz 命令变化率采用各自采样周期。

- 新版静止前车 L3 的实际制动比 L0 提前 0.32 s。两者均避撞，L3 在该样例多一次再介入，最小净距为 2.13 m，低于 L0 的 3.01 m。急刹样例两级首次实际制动均为 1.35 s，说明紧迫程度可能主导介入点。疲劳提前测试为合成等级。
- **验证范围** 简化纵向软件在环，障碍物有效性和保险杠净距由场景真值提供。实际减速度指模型积分得到的纵向加速度，静止速度钳零造成曲线在停稳时归零。接触改善包含预测净距与提前介入的共同作用。完整场景网格、感知误差、CARLA 制动标定和困倦驾驶员反应仍待验证。
