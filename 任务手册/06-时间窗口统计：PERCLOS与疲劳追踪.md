# ⏳ 阶段 5：PERCLOS 与时间窗口统计

> **本阶段目标**：理解为什么疲劳是"时间状态"而非"单帧状态"，学会 PERCLOS 的计算与验证。
>
> ⏱️ 预计时长：35 分钟 | 💻 你负责运行 + 模拟疲劳

---

## 🎓 你将学到什么

| 知识点 | 说明 |
|------|------|
| **为什么疲劳需要时间** | 正常人也会眨眼（0.1~0.4s），疲劳时闭眼持续 1~3s——单帧看不出区别 |
| **PERCLOS** | PERcentage of CLOSure——一段时间内眼睛闭合的时间占比，疲劳检测的黄金指标 |
| **滑动窗口** | 用一个固定长度的队列，新数据进来、旧数据出去，始终统计最近 N 秒 |
| **连续闭眼时间** | 从"开始闭眼"到"睁开眼睛"的时长，捕捉微睡眠 |

### 深入理解：PERCLOS 为什么是黄金指标？

Ji 2004 论文的结论：
> PERCLOS 与驾驶员的反应时间**高度线性相关**——PERCLOS 越高，反应越慢。

```
场景：30 秒窗口

正常驾驶:
  睁 ████████████░████████████░████  (眨眼 0.2s × 2 次)
  PERCLOS = 0.4 / 30 = 1.3%  → 正常

疲劳驾驶:
  睁 ██████░░░░░████░░░░░░░░░██████  (闭眼 2s + 1s + 4s = 7s)
  PERCLOS = 7 / 30 = 23%  → 报警
```

**滑动窗口队列示意**：

```
队列长度 = 30s × 15 FPS = 450 帧

[睁睁睁睁睁睁睁...闭闭闭...睁睁睁睁睁睁...闭闭闭闭闭...睁睁睁睁]
 ← 旧帧自动出队                    新帧入队 →

PERCLOS = 队列中"闭"的数量 / 450
```

### 步骤 2：模拟微睡眠验证 PERCLOS

这是验证系统是否有效的**关键测试**：

| 模拟场景 | 操作 | 预期结果 |
|------|------|------|
| **正常状态** | 自然看屏幕 60s，正常眨眼 | PERCLOS < 5%，状态正常 |
| **频繁眨眼** | 刻意快速眨眼 20 次/10s | PERCLOS 略升高但 < 10% |
| **长闭眼 1** | 闭眼 2 秒，睁开，再闭眼 2 秒 | 连续闭眼显示 2s → PERCLOS 升高 |
| **长闭眼 2** | 闭眼 5 秒 | 连续闭眼显示 5s → PERCLOS 显著升高 |
| **模拟微睡眠** | 30s 内闭眼 3 次，每次 3s | PERCLOS ≈ 9/30 = 30%，触发报警 |

### 步骤 3：调整 PERCLOS 窗口

改 `config.py` 中的 `PERCLOS_WINDOW_SEC`：

- 设为 **10s**：对短时闭眼更敏感，但也更容易误报
- 设为 **30s**（默认）：平衡灵敏度和稳定性
- 设为 **60s**：变化更平滑，但对突发事件反应慢

分别测试并记录你的感受。

### 步骤 4：确认时间逻辑

做以下测试，验证时间统计正确性：

- [ ] 闭眼时"连续闭眼时长"从 0 开始计数
- [ ] 睁眼后"连续闭眼时长"归零
- [ ] 闭眼时 PERCLOS 逐渐上升，睁眼后逐渐下降
- [ ] PERCLOS 超过阈值时状态条变红

## 🔧 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 正常眨眼也触发 PERCLOS 升高 | EAR 阈值太低，眨眼被误判为闭眼 | 调高 `EAR_THRESHOLD` 或降低 PERCLOS 灵敏度 |
| PERCLOS 变化太慢 | 窗口太大 | 减小 `PERCLOS_WINDOW_SEC` |
| PERCLOS 波动太大 | 窗口太小 | 增大 `PERCLOS_WINDOW_SEC` |
| 经常误报 | 阈值太敏感 | 调高 `PERCLOS_THRESHOLD` 到 0.25 或 0.3 |
